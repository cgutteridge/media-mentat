# Add an information source

Apply the [main skill](../../SKILL.md). Read the shared registry, private overlay,
and the request or setup coverage gaps. This subskill selects and validates a
source; [research](../research/SKILL.md) uses registered sources for particular works.

## Establish the gap

Identify the genre/medium, required evidence and scope: discovery lists, critical
reviews, bibliographies, content concerns, platform/edition facts or availability.
Use the actual taste clusters without copying them into shared defaults. A single
publisher catalogue or award list rarely supports every purpose. A user-supplied
URL is a candidate to evaluate, not automatic authority.

When asked to find sources, search for suitable candidates. During initial setup,
recommend researching sources for uncovered interests and carry it out if the
request authorizes research and the tools are available. If tools/access are
missing, record the concrete gap privately and explain what remains unsupported.
Do not claim a source was verified from its name or search snippet alone.

## Evaluate candidates

Open the actual source and inspect representative list/review pages. Determine:

- Publisher/author, editorial independence, expertise, transparent bylines/dates,
  and disclosed commercial incentives where relevant.
- Genre, medium, language/region, historical/current range and notable blind spots.
- What it supports: authoritative list membership, independent criticism, factual
  features, identity, availability, adjacency, or community leads.
- Spoiler exposure, whether usable metadata can be separated from plot-heavy text,
  and how to research while keeping delivery Unread-safe.
- Update cadence, date/version specificity, accessible archive/feed/API, and
  applicable terms, attribution, access requirements or rate limits.

Judge authority for the particular claim, not simply the domain's prestige.
For reviews, preserve disagreement and perspective rather than turn ratings into
universal fit scores. Reject unsuitable sources with a private reason, or keep
them as limited leads with an explicit status. Distinguish proposed, verified,
deferred and retired entries; access failures are not successful verification.

## Register and try

Add verified sources to private `sources.md`, deduplicating URL aliases. Record a
stable local source ID, canonical URL, role, genre/medium scope, evidence supported,
spoiler risk, verified date, cadence/limitations and access/ingest method. Extend a
legacy table or add a short source note when its columns cannot express this.
Keep credentials outside registry files. Do not require accounts or subscriptions
unless needed and available; record the limitation if they are not.

Try a small real research question. For a list, capture a dated membership sample
and its provenance; for a review, check that it supports a relevant craft/fit claim.
Store the trial privately. A successful source evaluation is not a finished
recommendation, and a publisher blurb is not an independent review.

Use a supported refresh script where it genuinely fits. Otherwise register manual
web research and source-linked notes as the working method; no new scraper is
required to add a source. Cache structured lists/facts through the existing store
and Evidence gate when practical, preserving the original source, timestamps,
work identity and medium. Do not force new genres into unrelated award categories
or claim the books/screen/short CLI supports a new medium.

## Finish and promotion

Report what was added, the gap it covers, remaining gaps and manual/automated
status. Return to setup, assessment or recommendation with usable evidence.
Source additions during personal use stay in the private overlay. General package
maintenance can promote a source into shared defaults after removing all user
associations, trial results and private selection rationale. Review that public
diff under the publication allowlist; never copy a personal registry wholesale.
